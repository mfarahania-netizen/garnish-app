# FORENSIC FINDINGS — Algorithm Quality (Personalization vs Heuristics)

**Dimension:** Is it real personalization/learned recsys, or a hand-tuned linear blend of heuristics dressed up as ML?
**Reviewer stance:** skeptical, evidence-only, no flattery («بدون تعارف»).

## Blunt verdict

It is a **hand-tuned linear blend of keyword/token heuristics with arbitrary weights** — there is no learning in the live path. The live ranker (`ranking.service.ts`) scores recipes by matching a fixed `signalTokenMap` against recipe text tokens and summing ~10 component scores with **hardcoded weights** (`tasteAffinity: 0.25, behaviorFit: 0.13, …`) that were never fit to data — the inline comments openly say they were carved by hand to "sum to 1.00". The genuinely interesting machinery — cuisine affinity, a collective "users like you cooked X" co-occurrence prior, feedback fit, the `scoreRecommendationCandidates` shadow scorer, the nDCG "learning proof" — **is entirely frozen in a shadow path that is wired to nothing the user sees** (`productUseEnabled: false`; the overlay keys never appear in `ranking.service.ts` or the live feature vector). The headline "engine learns, nDCG 0.29→0.73" comes from a **fully synthetic simulation where the same authors write both the behavior generator AND the relevance metric**, and the metric is cuisine-dominant by construction — the report itself admits effort marginal `−0.016` and skill `−0.0002` (i.e. two of the four "learned" dimensions contribute nothing). There are **no embeddings of users, no collaborative filtering in production, no learned model, and zero validation on a single real user.** Honest distance to a world-class recsys: **~10–15%** — solid plumbing, candidate-source diversity, and a real allergy gate exist, but the core (a learned model + valid offline/online eval) does not.

## The 3 things that would most move this dimension toward world-class

1. **Close the learning loop with a real trained ranker on real logs.** You already log `featureContributionLog` and impressions; add click/cook labels and train a LambdaMART/logistic ranker on a temporal split. This single change replaces the hand-typed weights (3 Critical findings) with learned ones and makes the system improvable from data instead of intuition.
2. **Promote the frozen shadow intelligence into production behind a flag, and ship collaborative filtering.** The cuisine-affinity + collective co-occurrence + feedbackFit code already exists and is good — it is just disconnected (`productUseEnabled: false`). Wire it live, add real item-item CF, and let online metrics (cook-rate, save-rate) decide if it beats the heuristic baseline.
3. **Replace the synthetic self-eval with an honest held-out offline + online eval.** The current nDCG proof is circular (same author writes behavior + relevance) and admits 2/4 dimensions do nothing. Evaluate on real future user actions (Recall@k / MAP, temporal split) and run a genuine online A/B with deterministic bucketing. Until then, no claim about recommendation quality is defensible.
