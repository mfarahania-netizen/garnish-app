# FORENSIC FINDINGS — The "Mind-Reading" Gap (does it feel like it gets the user?)

**Dimension:** Context-awareness, adaptation speed, transparency, proactivity — does the app feel like it reads the user's mind?
**Reviewer stance:** skeptical, evidence-only, no flattery («بدون تعارف»).

## Blunt verdict

It does **not** read the user's mind — it barely reads the clock. The live recommendation endpoint (`GET /recommendations`) takes only `userId` + `limit` (`recommendation.controller.ts:36-39`) and threads **no context whatsoever** into ranking: no time-of-day, no season, no weather, no occasion, no mood, no household, no "what did I cook this week," and no real pantry. The *only* contextual signal in the production ranker is a single `isIranWeekday(new Date())` boolean that mildly nudges one of ten score components (`effortFit`, ~0.10 weight) toward quicker meals on weekdays — and only if the user already has a quick-meal flag (`ranking.service.ts:212,225,358-377`). Everything that would feel like mind-reading is either **fake theater** (the Home "pantry rail" and "AI Whisper" are just slices of the same context-free rec list with a hardcoded "برای امشب/for tonight" string — `useHomeData.js:95-110`), **built-but-unwired** (the genuinely time-aware Daily Briefing has a controller but **no web screen calls it** — `briefing.controller.ts:7`, web only calls `/recommendations`), or **default-OFF dry-run** (the proactive meal-time/churn crons never dispatch; there is no push/email provider at all — `notification-scheduler.service.ts:6,30`). Transparency is a generic internal-score breakdown ("25% matches proven taste signals"), never a concrete, recognizable "because you cooked Ghormeh Sabzi" (`explainability.service.ts:20-26,51-67`). Honest distance to "it reads my mind": **~8-12%.** The scaffolding for context (a meal-context clock, a real pantry-match tool, proactive crons, a briefing composer) exists and is honestly built — but none of it is wired into what the user actually sees, so the felt experience is a static, time-blind list.

**How close to the vision ("it reads my mind"): ~10%.**

## The 3 things that would most move this dimension toward world-class

1. **Plumb a real `RecommendationContext` into the live ranker — starting with time-of-day → meal-slot.** Today the live path is context-blind by construction (`recommendation.controller.ts:36-39`). Pass `now` (and later season, recent cooks, pantry) and gate/boost candidates by mealType so 8am ≠ 8pm. This is the smallest change that converts "static personalized list" into "contextual assistant" and unlocks every later context signal.

2. **Ship a persistent pantry and make "cook with what you have" the contextual hero.** Add a `PantryItem` model, default `match_pantry_recipes` to read it (today it requires re-typing every message — `match-pantry-recipes.tool.ts:30`), replace the fake Home "pantry rail" (`useHomeData.js:95-101`) with real pantry matches, and fire a proactive low-effort nudge ("you have X, Y, Z — cook this tonight"). Pantry awareness is the single most mind-reading-feeling capability and is currently absent end-to-end.

3. **Wire the Daily Briefing to a real screen + a real push channel, and make explanations concrete.** The time-aware briefing is built but dark (`briefing.controller.ts:7`, no web caller) and proactivity is default-OFF dry-run with no push provider (`notification-scheduler.service.ts:6,30`). Surface `GET /briefing/today` as Home's hero, turn on consented meal-time/low-pantry/saved-not-cooked triggers over a real push channel, and replace the score-percentage explanations (`explainability.service.ts:11-26`) with recognizable "because you cooked X" reasons. Together these turn latent scaffolding into a system that suggests before being asked and explains itself in human terms.
