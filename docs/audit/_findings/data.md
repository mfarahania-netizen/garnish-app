# FORENSIC AUDIT — Dimension: Data, Scale, Cold-Start, Privacy

## Verdict (blunt, بدون تعارف)

The personalization loop is **structurally single-user and largely cold forever**. There is no real collaborative signal: the one function named `getCollaborativeRecipes` is a declared-health-goal join, not collaborative filtering, and the only true population model (`collective-signal.ts`) is shadow-only and **never wired** to the live ranker. The runtime profile that feeds the allergy filter, recsys, AI and gamification (`getLivingUserProfile`) is **hardwired to empty observations** — it is declared-only by construction, so behavior never enters the live profile. Personalization that *does* exist is content/keyword fit ranking over a tiny event history, gated behind demanding maturity thresholds (14 active days + 120 qualified events for "reliable") that almost no real user will hit early. On privacy, the parts that are built are genuinely good (transactional cascade erasure with PII-free proof, a per-model retention map, consent-purpose gating in the *offline* signal layer) — but the **runtime ingest path writes every event with no consent check at all**, and retention is dry-run only so behavioral data accumulates indefinitely in practice. **How close to the world-class vision: ~25%.** The privacy *scaffolding* is ~60% of the way there; the actual recommendation data flywheel is ~15% — it cannot get warm at realistic scale and has no network effect.

## The 3 things that would most move this dimension toward world-class

1. **Close the runtime behavioral loop.** Make `getLivingUserProfile` hydrate observed taste/effort/skill from persisted observations (keeping allergies declared-only), and persist the *full* observation contract so confidence/consent/privacy survive. Right now the behavioral engine exists but is disconnected from the live profile — this is the single biggest gap.
2. **Build a real population/collaborative prior and wire it live.** Promote `collective-signal.ts` (or a proper item-item / matrix-factorization model over observed engagement) into `ranking.service.ts` as an additive, allergy-gated prior. This is what creates the network effect a billion-dollar recsys needs and what rescues every thin/cold user from "population of one."
3. **Make privacy operational, not just scaffolded.** Enforce consent purpose at ingest (`trackEvent`), stamp purpose on every event, and actually run the retention prune on a schedule. The erasure/audit foundation is strong; the collection and deletion ends are where EU exposure currently lives.

### 4-line summary
- **dimension:** Data, scale, cold-start, privacy
- **verdict:** Loop is single-user and mostly cold-forever; live profile is declared-only by hardwiring, no collaborative/network signal is wired, and consent isn't enforced at ingest — ~25% of the vision. Erasure/retention *design* is the bright spot.
- **#critical:** 3
- **biggest problem:** `getLivingUserProfile` is hardwired to empty observations (profile-read.service.ts:112), so behavior never enters the live profile — there is no warm-up and, combined with no live collaborative signal, every user stays cold forever.
