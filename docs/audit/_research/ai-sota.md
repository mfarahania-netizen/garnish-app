# Garnish AI — State of the Art Research (2025–2026)

> Distilled, source-cited synthesis of the actual state of the art across 7 AI dimensions, mapped to Garnish's two pillars:
> **L2a** = the omnipresent, DB-grounded, real-time, tool-using user assistant ("never lost ANYWHERE").
> **L2b** = the admin-analytics AI (all app+user data → ~200 categorized parameters, supervised positive changes).
>
> Skeptical posture: every claim below is grounded in a named real system, paper, or benchmark. Where vendor marketing overstates autonomy or benchmarks are inflated, it is flagged.

---

## 0. The single most load-bearing findings (read these first)

1. **For ~1,008 structured records, do NOT build vector RAG.** The decision threshold from 2025 practitioner + academic consensus: <100 docs → in-context clearly wins; 100–1,000 → in-context usually still wins on precision/simplicity; >1,000 heterogeneous docs → RAG becomes necessary. Garnish's ingredient corpus sits squarely in the band where **in-context curated KB ("LLM wiki" / Cache-Augmented Generation) + tool-calling beats a vector store** on precision, latency, and maintainability — and eliminates the #1 RAG failure mode (retrieval-miss). *(MindStudio LLM-wiki-vs-RAG; Karpathy 2025; CAG / Chan et al.)*

2. **The semantic layer, not text-to-SQL, is the grounding substrate for L2b.** dbt's 2026 benchmark: Semantic Layer hit 98.2% (Claude Sonnet 4.6) / 100% (GPT-5.3) on in-scope questions vs 84–90% for raw text-to-SQL. The killer property: *"With text-to-SQL, failure looks like a plausible but INCORRECT answer; with the Semantic Layer, failure looks like an ERROR message."* For a founder-facing panel, silent-wrong is fatal. *(getdbt.com/blog/semantic-layer-vs-text-to-sql-2026)*

3. **Garnish already has the crown jewel and it is OFF / unplugged, not missing.** There is no live LLM in any production path today (the user-facing reply is `composeDeterministicReply`, a string template). The live Gemini path is fully wired behind a hard, fail-closed allergy gate but gated off by a triple env switch. The structured moat (GRIS, taste/texture/cookingBehavior) reaches the assistant only via keyword `contains` matching. **The gap is "flip + enrich + add generation inside the gate," not "build from scratch."**

4. **Retrieval being right ≠ answer being grounded.** Stanford-cited finding: up to **40% hallucination even when the correct data is retrieved**. Faithfulness must be verified at *generation* time, not assumed from retrieval. *(clarityarc.com; RAGAS/DeepEval)*

5. **Persian-first breaks English assumptions.** Hallucination detectors degrade in low-resource languages (arXiv 2601.16766). Every eval number from English benchmarks must be re-earned on a Garnish Persian golden set.

## Dimension 2 — Grounding an LLM in a STRUCTURED domain DB (L2a + L2b)

| SOTA technique | Verdict for Garnish |
|---|---|
| **In-context curated KB / Cache-Augmented Generation (the "LLM wiki")** | **RECOMMENDED for L2a.** Serialize the whole stable structured corpus into context; model reasons over it directly. ~1,008 ingredients is exactly the band where this beats RAG on precision + latency + debuggability and eliminates retrieval-miss. *(MindStudio; Karpathy; CAG/Chan et al.)* |
| **Prompt / context caching** | **Makes in-context economically viable.** Anthropic cache reads ~$0.30/M vs $3.00/M (~90% cheaper, up to 85% lower latency), min 1,024 tokens. Cache prefix = `[system rules + ingredient table + GRIS schema]`; per-screen recipe GRIS injected below the cache boundary. *(Anthropic, Gemini, OpenAI, Bedrock GA Apr 2025)* |
| **Tool/function-calling over the structured DB** | **The correct backbone for facts + mutations.** Typed `get_ingredient`, `find_substitutes`, `check_allergen`, `scale_recipe`. Graph-Grounded LLMs (arXiv 2503.10941) show function-calling a graph library cuts hallucinations vs free-generation. Reuse Garnish's `assessRecipeFit`/`analyzeRecipeIntegrity` AS TOOLS. |
| **Text-to-query (text-to-SQL)** | **L2b ONLY, and never free-form.** SOTA is ~10–17% on realistic enterprise schemas (Spider 2.0). Pre-define ~200 params as named parameterized verified queries; LLM SELECTs + parameterizes; execute-verify before surfacing. Benchmarks inflated (52.8% annotation errors in BIRD, 66.1% in Spider 2.0-Snow per 2026 VLDB/CIDR). |
| **GraphRAG / KG grounding** | **For the HARDEST multi-hop only.** during-cook chains (substitute → changed cookingBehavior → affected technique → fix) and L2b correlations (technique ↔ failed-cook). Model ingredient/recipe/technique nodes with substitutes/uses/affects edges. Don't graph simple lookups. *(MS GraphRAG, Neo4j, arXiv 2502.13247)* |
| **Hybrid search (BM25 + dense + RRF + cross-encoder rerank)** | **Reserve for UNSTRUCTURED text only** (recipe prose, chefTips, future reviews), always behind a structured metadata pre-filter (allergen-safe + dishType FIRST). Pure semantic misses Persian dish/ingredient names; pure keyword misses synonyms. NOT needed for structured lookups. |
| **Faithfulness eval as CI gate + inline self-check** | **Non-negotiable safety layer.** RAGAS/DeepEval atomic-claim verification + in-request groundedness judge that blocks/re-queries before any safety answer or "positive change" ships. **Budget extra Persian eval** — detectors degrade in low-resource languages (arXiv 2601.16766). |
| **Constrained / grammar-constrained decoding + span-level citation** | **Turns "no hallucination" into a decoding-time guarantee for data slots.** Model can only emit ingredient IDs / enums / citations that EXIST in the DB; each claim carries a field pointer ("per USDA-locked nutrition"). Constrain the SLOTS, not the prose — over-constraining hurts reasoning (arXiv 2604.06066). *(Outlines, structured outputs)* |

**Recommended L2a architecture:** **HYBRID of in-context cached corpus + tool-calling, NOT vector RAG.** Allergy gate stays DETERMINISTIC and OUTSIDE the LLM. Constrain the data-bearing slots. Add span-level provenance. Defer any vector DB until a genuinely large unstructured UGC corpus exists.

**Pitfalls:** defaulting to vector RAG for 1k records; "retrieval correct = grounded" fallacy (40% hallucination); trusting the LLM for allergens/arithmetic; free-form text-to-SQL anywhere user-facing; over-constraining decoding; assuming English eval transfers to Persian; **stale-cache drift** (Garnish is actively source-locking USDA + rewriting steps → need cache-invalidation tied to data writes); coarse URL-style citations vs field-level provenance.

*Sources:* mindstudio.ai llm-wiki; ragflow.io rag-review-2025; anthropic.com prompt-caching; futureagi agentic-rag-2025; arxiv 2503.10941, 2502.13247; spider2-sql.github.io; vldb 2026 p5-jin; deepeval faithfulness; arxiv 2305.13971, 2604.06066, 2601.16766.

| SOTA technique | Garnish mapping |
|---|---|

| **On-device small model + cloud fallback** (Apple Foundation ~3B; Gemini Nano) | Offline resilience (flaky kitchen Wi-Fi) + latency floor for trivial intents. | **Inference-level latency** (EAGLE-3 spec-decode 2.8–5.8×, FP8, continuous batching) | Only relevant **if/when Garnish self-hosts** a fine-tuned Persian culinary model. Premature today; the path if cost/latency/Persian-quality force self-hosting. |

**Pitfalls:** realtime p95 latency hits 2.5–3.0s on noisy audio / long tool chains (kitchen = that environment — cap tool-chain depth, pre-warm caches); speech-to-speech hides the transcript (makes deterministic allergy gating harder — surface tool calls as explicit auditable steps); semantic-cache confidently-wrong neighbors; on-device weak at hard multimodal + likely weak in Farsi; constant video streaming is expensive (frames on demand only); **generic recipe Q&A is commoditized — the during-cook, photo-grounded, failure-recovery moment is the hard part and where Garnish must excel**; don't over-narrate (default to silence).

## Dimension 4 — Agentic analytics / "AI data analyst" for the admin panel (L2b)

**Architectural verdict: do NOT let an LLM free-write SQL. Put a deterministic SEMANTIC LAYER between model and data; the LLM only chooses metrics/dimensions; the engine generates queries deterministically. On top: a metric-tree decomposition engine + proactive anomaly monitoring + a narrating multi-agent layer with an explicit "out-of-scope / I can't answer" escape hatch.**

| SOTA technique | Garnish mapping |
|---|---|
| **Semantic layer as grounding substrate** (dbt MetricFlow — Apache-2.0 since Dec 2025 — Cube, AtScale) | Define metrics (completion, step drop-off, swap rate, rating, retention) + dimensions (dish, step, ingredient, cohort, skill-level, screen) over events/recipes/ingredients/GRIS/L0. LLM picks; engine queries. **98–100% vs 84–90% for text-to-SQL; failure = error message, not silent-wrong.** |
| **Metric-tree / decomposition-tree driver analysis** (Power BI Decomposition Tree + Key Influencers, Tableau Pulse Top Drivers/Detractors, ThoughtSpot SpotIQ) | **This IS "which dish has a problem and WHY"** as a standard primitive. Per-dish metric tree decomposed by recipe/step/ingredient/cohort → "completion fell 12%, driven by Step 4 of Ghormeh Sabzi for beginners" with contribution math done **deterministically**. |
| **Automated insight taxonomy (fixed catalog of insight TYPES)** — path to ~200 params | Tableau Pulse ships 13 explicit types (Period-over-Period, Correlated Metrics, Outliers, Forecast, Trend-Change, Top Drivers/Detractors, Concentrated Contribution, …). **~200 params = (insight-types) × (metric families) × (entities).** Each param = one deterministic query; LLM only narrates. Auditable, testable, no 200 bespoke dashboards. |
| **Proactive monitoring + anomaly detection pushed as narrative** (Tableau Pulse, Anodot, Argos LLM-AIOps 2025) | Nightly scans flag "saffron swap spiked 3×", "beginner abandonment on dish X breached threshold" with driver attached. Same substrate later feeds founder-supervised changes. *2026 shift: AI investigates proactively, not pull-a-dashboard.* |
| **Hierarchical multi-agent analyst with explicit "out"** (Insight Agents 2026: 89.5% question-level acc, P90 <15s) | Manager (out-of-domain detect + route) over workers (presenter vs insight-generator); math via external calculation tools; **explicit refusal when a question exceeds the data = the single most important anti-hallucination lever** for a founder-facing panel. Mirrors L2a's hard allergy gate philosophy. |
| **Rigorous grounded eval** (InsightBench, InsightEval; rubric LLM-as-judge with bias correction) | Held-out set of known dish/cohort facts scored on **Correctness / Completeness / Relevance**, schema-constrained JSON, pinned temperature/seed. Without this harness, "AI data analyst" is unfalsifiable. |
| **Product-analytics-native agents as reference UX** (Amplitude AI Agents/Compass, Mixpanel Spark+Signal, PostHog Max) | Concrete diagnostic primitives owed: funnel drop-off per step, retention by cohort/skill-level, "which behavior predicts week-4 retention." **Garnish's edge:** join behavior to GRIS food-science + per-ingredient structured data → "why" reaches recipe-content level, a moat no generic PA tool has. |

**Pitfalls:** raw text-to-SQL fails SILENTLY (worse than no answer); warehouse-native agents (Cortex Analyst, Genie) are boundary-locked + curation-heavy (one Genie case 53%→100% only after remodeling — *the curation IS the work*); LLM-as-judge is itself biased (calibrate against human-labeled Persian examples); vendor "agentic autonomy" massively overstated (autonomy is in narration, not trustworthy unsupervised action); **never let the LLM compute the numbers** (push math to deterministic engines); **Garnish is event-poor today (swaps emit ZERO events, ranker ~0% learning) — the "capture every second" gap must close FIRST** or the admin AI narrates over sparse/biased data; insight degrades without domain grounding (inject GRIS/ingredient ontology).

*Sources:* getdbt.com semantic-layer-vs-text-to-sql-2026; getdbt.com open-source-metricflow; help.tableau.com pulse insight-types; tableau.com agentic-analytics; inforiver decomposition-tree; arxiv 2511.22884, 2601.20048, 2602.04261, 2507.12472; databricks.com what-is-agentic-analytics.

## Dimension 5 — Supervised autonomy / human-in-the-loop ops (L2b)

| SOTA technique | Garnish mapping |
|---|---|
| **LangGraph `interrupt()` / HITL middleware (durable pause-resume)** | Reference impl of "AI proposes, human approves, AI executes" with crash-safe state. Every proposed change = an interrupt the founder approves/edits/rejects; agent never mutates DB until the gate clears; restart doesn't lose the pending proposal. |
| **Claude Agent SDK permission model: deny-first + reversibility-weighted risk + `canUseTool`** | **Garnish already runs on the Claude Agent SDK** — adoptable, not aspirational. | **Autonomy tiers + escalation triggers** (CSA/NIST Agentic Profile; EU AI Act Art. 14, enforced Aug 2026) | Start L2b at **Tier 1 (propose-only, founder approves everything)**; measure per-change-type approval/override rates; graduate only low-risk categories (dishType tagging) to auto-apply; keep high-blast-radius (substitutions feeding the allergy filter) **permanently human-gated.** Escalate on blast-radius/reversibility/novelty, not confidence alone. |
| **Progressive delivery** (shadow mode, canary, feature flags, ringed rollout) | Decouple "apply" from "expose." Ship an AI-rewritten step behind a flag to 1% of cooks; **use Garnish's L0 behavioral signals (cook_complete, abandonment, swap) as the canary metric**; auto-rollback on regression, promote on improvement. |
| **Blast-radius tiering + scoped execution + rollback-as-policy** | Writes confined to a staging copy / bounded row-set; pre-write "what will this change" analysis surfaced to the founder; automatic revert if post-apply signals trip. Protects the moat corpus. |
| **Reasoning-linked audit trails + async correction loop + `@control()` hot-reloadable policy** | Log rationale + tool I/O + policy evals per proposal; when the founder edits/rejects, capture the NL reason and feed it back (Galileo Autotune-style) → the ~200-param AI **learns instead of staying rules-based** (serves the "learning not rules" bar). Audit trail = EU AI Act compliance artifact. |

**Pitfalls:** safety via prompt instead of code (prompt injection defeats it — allergy/destructive limits MUST be deterministic policy outside the LLM); **approval fatigue / rubber-stamping** (batch + rank by impact, auto-apply truly low-risk, reserve attention for high-blast-radius); raw LLM confidence is uncalibrated (measure on Garnish's own data); audit logs lacking reasoning / not tamper-evident; no staging path = irreversible moat mutation; skipping crash-safe state; over-automating too early (start fully-supervised, earn autonomy per category, keep irreversible/allergy actions human-in-the-loop indefinitely).

## Dimension 7 — EXISTING Garnish AI (baseline, code-grounded)

**The hard truth: there is NO live language model in any user path today.** `POST /ai/chat` → `ChatOrchestrationService` → `AiOrchestratorService` → in production a `StubModelProvider`. The user-facing reply is `GroundedReplyService.composeDeterministicReply` — a string-templated SAFE recipe list. "AI chat" = retrieval + template, zero generation. Both pillars are ~0% on the generative axis. **The strong part is the grounding/safety scaffold, not the intelligence.**

**What's genuinely moat-grade and must be PRESERVED:**
- **Retrieve-then-hard-filter grounding** (`buildGrounding()`): establish allergy set FIRST via `getLivingUserProfile` → retrieve ≤12 via read-only `search_recipes` → reload `FIT_SELECT` → **HARD allergy gate reusing `assessRecipeFit` + `analyzeRecipeIntegrity`** (drops any recipe whose declared∪derived allergens intersect the user's set) → surface ≤5. **Fails closed** (profile can't load → surface nothing, never guess). This is exactly the "guardrails around grounding" 2025 production discipline — already built.
- **Live LLM rails fully wired but OFF behind a triple env switch** (`GeminiModelProvider`, default `gemini-2.5-flash`; `AI_PROVIDER=gemini` AND `AI_LIVE_ENABLED=true` AND real `GEMINI_API_KEY`, plus `AI_CHAT_LIVE_ENABLED`). Live path: `buildLivePrompt` (injects ONLY the pre-filtered safe set, NEVER declared allergens) → guards → `screenLiveOutput` (post-gen gate, fails closed). **OFF for sound reasons:** empty cost-rate catalog (cost honestly null), output-gate not pilot-proven, prior Gemini key leak made them conservative. **The gap to L2a is "flip + harden," not "build."**
- **Data moat** (`schema.prisma`): Ingredient `tasteProfile`/`textureProfile`/`cookingBehavior`/`nutritionConfidence`/`dietFlags`/`allergens`/`substitutionOptions` per ~1008 ingredients; `Recipe.gris` (GRIS v2.1); L0 living profile (declared + SignalObservation-hydrated, reconciled allergy dimension). **Today only a TINY slice reaches the assistant** — `search_recipes` keyword `contains` + `suggest_substitutions`. **taste/texture/cookingBehavior/GRIS are essentially UNUSED by the assistant.** This is the single biggest L2a opportunity.
- **8 read-only tools, NO agentic loop** — `AiAssistService` invokes EXACTLY ONE tool per HTTP call, route-picked, no LLM planner, no chaining. Clean allow-list (great for safety) but a human router instead of a planner. L2a needs a grounded model to select/chain these tools.
- **L2b substrate** (`AnalyticsIntelligenceService`): real funnels/trends/cohorts/product-intel, every metric REAL or explicit `awaiting_pilot`, never fabricated, aggregates only. **But NO LLM, no ~200-param categorization, no narrative/root-cause, no change-making.** It produces numbers; L2b needs an agent that reads them + raw events and writes insights.
- **Cost/safety/observability harness** (ahead of most startups): orchestrator pipeline (snapshot → prompt-injection guard → cost controller → safety guard → model → nutrition-claim guard → `AiCallLog` on EVERY terminal path), persisted daily budget + spend alerts, eval harness (output-safety regression corpus, pilot-readiness gate, live-smoke specs). **Flipping live LLM on is LOW-risk operationally.**

**Pitfalls / misconceptions to kill:** "we have AI" (there's no live model); the allergy gate is the crown jewel — no L2a path may bypass it or feed declared allergens into a prompt (streaming makes post-hoc `screenLiveOutput` harder — gate per segment); live Gemini is OFF for real reasons (don't flip naively without populating cost rates + running pilot/output-safety gates); the structured moat is NOT currently reaching the assistant; `AnalyticsIntelligenceService` is deterministic metrics, not analytical AI; the 8-tool layer looks agentic but isn't; **swaps emit ZERO observability events — the interactions L2a/L2b most need to learn from are partly uninstrumented.**
