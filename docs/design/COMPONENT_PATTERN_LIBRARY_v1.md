**Status:** Specification — DRAFT for Founder/Reviewer audit; no component claimed implemented. **Authority:** Constitution A1.8 + External Audit Patch v1.0.1; GES v1; Implementation Guide. **Scope rules:** no public feed/chat/DM, no leaderboard, no social profile/follower, no medical-claim, no autonomous-agent components — such patterns are out of this library by constitution. Every data-dependent component below includes empty/loading/error behavior; every AI/recommendation/nutrition component includes safety/explainability rules. Tokens only; motion via `lib/motion.js`; events per ADR-0001 Envelope.

## Library-wide rules
1) Forbidden component classes (constitutional): public feed/chat/DM, leaderboard, social profile/follower, medical-claim, autonomous-agent UI — proposals for these are rejected at review, not designed "off". 2) Data-dependent components without their empty/loading/error rows here = spec bug; file an issue, don't improvise. 3) AI/recommendation/nutrition components inherit the safety stack: disclosure glyph, guard-filtered content only, Why where recommending, badge where numbering. 4) Every component maps to GES sections + Guide rules; conflicts escalate to UX, never solved locally. 5) New components enter only via UX-approved addition to this file (Decision Log), then implementation ticket.

## Appendix A — Critical Component Deep Dives

### AI Sheet
- Primary risk: silent or implied writes (plan/list mutation without explicit confirm) and tool-scope creep beyond the four E47 tools.
- Data dependency: BehavioralContextSnapshot (mandatory — absent ⇒ fail-fast, safe-degraded notice), anchored object payload, streamed Orchestrator response, guard verdicts.
- Required events: ai_sheet_open(objectType/Id) · ai_call(runId, snapshotHash) · ai_write_confirmed / ai_write_declined · why_open on embedded recs.
- Required safety/explainability: disclosure header (glyph+"AI"), guard-refusal pattern with alternatives, NutritionBadge on any number, Why on any embedded recommendation, confirm button is a real user action (no auto-focus-enter trap).
- Mobile behavior: bottom sheet ≤1 screen height, drag-dismiss, keyboard pushes sheet (composer visible), returns caller scroll position.
- RTL/LTR behavior: sheet slides from bottom (direction-neutral); context chip, stream text and action order follow dir; confirm/decline order mirrors.
- Empty/loading/error behavior: loading=snapshot spinner-in-header ≤300ms then skeleton lines; guard-refusal is a designed state (not error); network error=inline ErrorState with retry; offline=clear notice, composer disabled.
- Implementation trap: reusing the Companion screen in a modal "to save time" — breaks anchoring, context chip and write-confirm flow.
- Reviewer rejection criteria: any write path without explicit confirm e2e · missing disclosure header · tool call outside the four · refusal rendered as raw error · sheet that navigates away.

### Recipe Card
- Primary risk: feed-ification (endless vertical card streams) and broken/misleading imagery.
- Data dependency: recipe summary (title, photo?, time, difficulty), saved/dismissed state, rail explanation payload (rec context only).
- Required events: impression(position) · click · save · dismiss(+undo_restore) — Envelope fields surface/context mandatory.
- Required safety/explainability: in recommendation contexts the Why chip is mandatory (payload-fed); image-missing uses branded placeholder, never another dish's photo.
- Mobile behavior: 4:3 media, full-card tap target, swipe-end=save / swipe-start=dismiss with 5s undo toast; long-press preview sheet.
- RTL/LTR behavior: swipe semantics defined logically (start/end, not left/right); title/meta alignment follows dir; photo never mirrors.
- Empty/loading/error behavior: skeleton twin matches exact layout (zero CLS); list-level empty handled by EmptyState; image error→placeholder silently.
- Implementation trap: hiding save/dismiss behind swipe only — must also exist in long-press menu for non-pointer/accessibility users.
- Reviewer rejection criteria: stretched/tinted photos · >2-line title clamp broken · swipe without undo · Why missing in rail · raw hex/inline motion.

### Cook Step
- Primary risk: distraction and mid-cook data loss (step/timer state evaporating on interruption).
- Data dependency: ordered steps (food-specific text ≤2 lines), optional step media, ingredient refs by ingredientId, timer specs.
- Required events: cook_step_view/complete(stepIdx) · timer_start/finish/missed · cook_abandon(stepIdx).
- Required safety/explainability: none AI-specific (no AI interrupts mid-step; help only via user-invoked AI Sheet); ingredient peek shows AllergenMark when relevant.
- Mobile behavior: one step per screen; ≥56px bottom prev/next; wake-lock on; survives backgrounding (state persisted); optional voice next/back.
- RTL/LTR behavior: prev/next placed by logical start/end and icons mirrored; numerals per locale formatting layer.
- Empty/loading/error behavior: n/a-empty (entered with recipe); media error→text-only step; wake-lock/timer API failure→calm inline notice, flow continues.
- Implementation trap: rendering the whole recipe in a scroller with a step highlight — kills the distraction-free contract and timer anchoring.
- Reviewer rejection criteria: text <22px at default · controls reachable only mid-screen · timer loss on step change (e2e) · notifications overlaying steps · Celebrate firing more than once.

### Meal Slot Card
- Primary risk: AI auto-commit — a plan mutated without the user's explicit confirmation (E47 Annex violation).
- Data dependency: slot identity (day/meal), suggestion payload (recipe + confidence + explanation), lock/user-set flag.
- Required events: slot_suggestion_shown · slot_fill_confirmed/declined · slot_clear(+undo) · why_open(slotId).
- Required safety/explainability: pending-confirm visual state distinct from filled; confidence badge on 100% of AI fills; Why chip on AI fills; declined suggestions suppressed like Whisper dismissals.
- Mobile behavior: drag-to-move with keyboard/menu alternative; confirm/decline buttons in-card lower edge; tap opens slot AI Sheet.
- RTL/LTR behavior: week column order follows locale calendar/dir; drag axis unaffected; badge/chip order mirrors.
- Empty/loading/error behavior: empty=invite affordance ("add or ask AI"); loading=slot skeleton; save-error=inline retry keeping the pending suggestion visible.
- Implementation trap: treating Whisper-accept as plan-write authorization — accept opens pending-confirm state; the write needs its own confirm.
- Reviewer rejection criteria: any auto-filled committed slot in e2e · missing confidence badge on an AI fill · undo absent on clear · drag without non-pointer alternative.

### Nutrition Badge
- Primary risk: implied medical certainty — numbers without source state, or invented zeros (trust + Reg.1924/2006 exposure).
- Data dependency: nutritionSourceStatus from the data layer (source-locked / estimate / unavailable) per EPIC 12; source name for verified.
- Required events: nutrition_badge_view(state) · nutrition_source_open.
- Required safety/explainability: numbers render ONLY when source-locked; estimate state uses hedged copy; unavailable says "Not available" (never 0); persistent calm disclaimer on nutrition panels; banned-words list applies to all adjacent copy.
- Mobile behavior: badge inline with the number, 44px hit-area; verified-tap opens small source sheet.
- RTL/LTR behavior: dot+label order follows dir; numerals via formatting layer; badge never separated from its number by wrapping.
- Empty/loading/error behavior: loading=text skeleton inline; fetch error⇒fall back to "unavailable" presentation (fail-safe), log event.
- Implementation trap: copy-pasting badge markup per surface — single shared component only; duplicates drift into unbadged numbers.
- Reviewer rejection criteria: any numeric nutrition without a badge (grep audit) · fake zero for missing data · color-only state difference · second badge implementation in the tree.
